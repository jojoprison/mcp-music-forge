# Яндекс.Музыка: где проходит гео-граница и почему файл приходит на 30 секунд

**Дата:** 2026-09-21 · **Повод:** поддержать ссылки `music.yandex.ru` в боте.
**Проверочный трек:** `music.yandex.ru/album/40348473/track/147503042` — SosoCamo, «lookin back»,
заявленная длительность 125.8 с.

## Итог одной строкой

Гео-блок стоит **только на API**, раздача файлов открыта всему миру, а без подписки API отдаёт
валидный с виду ответ и 30-секундный огрызок. Отсюда обе конструкции в провайдере: прокси только
для API и два независимых гейта против огрызка.

## Замеры

| Что спрашивали | Откуда | Ответ |
|---|---|---|
| `api.music.yandex.net/tracks/147503042` | Таиланд (машина j) | **451** Unavailable For Legal Reasons |
| то же | Сингапур (`coco`, прод) | **451** |
| то же | `aura` (AdminVPS, RU) | **200** |
| то же | `bts`, `vpn-gateway` (Yandex.Cloud, RU) | **200** |
| `storage.yandex.net` (сам файл) | Таиланд | **410** на несуществующий объект — то есть блока нет |
| подписанная ссылка на трек | Таиланд, без прокси | **481 115 байт скачаны** |
| `oauth.yandex.ru` | Таиланд | **302** — авторизация работает без прокси |
| длительность скачанного без токена | ffprobe | **30.000 с** против заявленных 125.8 с |

Сетевая связность прода с РФ есть: `coco` достаёт `155.212.245.167` и `111.88.254.249` по ssh,
задержка 188 мс. Для API этого достаточно — через прокси идут килобайты, мегабайты аудио нет.

## Что проверено и НЕ является причиной

- **Не отсутствие cookies и не «Яндекс нас забанил».** Отказ 451 приходит одинаково на любой
  запрос с зарубежного адреса, включая анонимный `curl` без единого заголовка.
- **Не поломка одной библиотеки.** `yt-dlp` и `yandex-music` упали одинаково и в одном месте.
- **Не гео-блок на раздаче.** `storage.yandex.net` отвечает `410` (нет объекта), а не `451`;
  отличать эти два кода здесь принципиально — иначе прокси городят для всего трафика.

## Отдельно: встроенный в yt-dlp экстрактор мёртв

`yt-dlp 2025.09.23`, две разные ссылки, один результат:

```
WARNING: [yandexmusic:track] Failed to parse JSON: Expecting value in ''
ERROR: TypeError: 'NoneType' object is not subscriptable
```

Экстрактор в списке присутствует (`yandexmusic:track/album/playlist/artist`) и на этом обманывает:
имя есть, функциональности нет — он зовёт снесённые Яндексом ручки `handlers/*.jsx`. Плагин
[`yt-dlp-yandex-music`](https://pypi.org/project/yt-dlp-yandex-music/) (свежий, MIT) чинит это,
но на момент разбора у него ноль звёзд и авторская пометка «vibecoded, не проверен», а главное —
он проксирует весь трафик разом, включая аудио. Взяли библиотеку `yandex-music` (1.3k звёзд,
LGPL-3.0) и качаем файл своим `httpx`.

## Почему гейтов два, а не один

Флаг `preview: true` в `download-info` — честный и первый. Но он приходит **от той же стороны**,
которая может отдать огрызок, поэтому второй гейт меряет уже скачанный файл: фактическая
длительность против метаданных, порог 0.8. Третий случай выяснился на ревью: `mutagen` возвращает
`None` не только когда метаданных нет, но и когда аудио в файле нет вовсе — страница ошибки с
кодом 200, оборванная закачка, кончившееся место. Такой файл тоже не выпускается наружу.

## Туннель на проде: `socks5h`, иначе IPv6 рвёт соединение

Прод завели в тот же день; между «туннель поднят» и «джоба прошла» оказался ещё один слой.
Замеры с `coco` на один и тот же адрес:

| Проверка | Результат |
|---|---|
| `curl` напрямую | **451** |
| `curl --socks5-hostname 127.0.0.1:1080` (имя резолвит РФ-узел) | **200** |
| `curl --socks5 127.0.0.1:1080` (имя резолвится локально) | **000** — соединение не встало |
| `getent hosts api.music.yandex.net` с `coco` | `2a02:6b8::5:246` — **IPv6** |

Причина: локальный резолв отдаёт IPv6, которого ssh-туннель не несёт. Библиотека с
`socks5://` ведёт себя так же, как `curl --socks5`: `NetworkError … Connection closed
unexpectedly` при полностью доступном порте 1080 — то есть отказ выглядит как мёртвый туннель,
а туннель жив. Лечение — схема **`socks5h://`**: имя уходит на ту сторону и резолвится уже там.
После замены та же библиотека в том же контейнере отдала `mp3 320 kbps, preview=False, 125.8 с`.

Стоило это одной боевой джобы: она упала с текстом «Яндекс.Музыка временно не отдала файл» —
классификация сработала верно (сетевой отказ → временный), и именно поэтому причина не была
видна из сообщения.
