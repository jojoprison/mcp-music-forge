## INF-1 — каталог джоб растёт без ограничения и никем не чистится

- **Статус:** open · 🟡 low
- **Что:** `data/jobs/<job_id>/` хранит и оригинал (`original/`), и результат (`final/`), и
  обложку — навсегда. Ничто их не удаляет: ни по возрасту, ни по объёму, ни после отдачи
  файла пользователю.
- **Замер 29.08.2026:** **925 МБ** в 120 каталогах, то есть ~7.7 МБ на задание. Диск 75 ГБ,
  занято 19 ГБ (27%). До заполнения далеко, но рост линейный и ничем не ограничен.
- **Почему не критично сейчас и почему всё-таки карточка:** запас на годы при нынешнем темпе.
  Но отказ, когда он наступит, будет не «кончилось место под музыку», а **встанет sqlite** —
  и вместе с ним api и телеграм-бот, который живёт в том же процессе. То есть цена ошибки
  та же, что у [API-1] (см. `../DONE.md`): один ресурс — два продукта.
- 🛑 **Чего делать НЕ надо:** чистить `original/` сразу после транскода. Досыл
  (`core/services/redelivery.py`) повторяет упавшие джобы и берёт файл с диска; агрессивная
  чистка превратит «должок» в вечный `audio file missing on disk` до исчерпания попыток.
- **Простейший фикс — по лестнице:**
  1. Удалять `original/` у джоб старше N дней, у которых доставка закрыта
     (`delivery.delivered_at IS NOT NULL` или ждущих нет вовсе). `final/` оставить.
  2. Если мало — удалять каталог целиком по возрасту, cron'ом в том же воркере, где уже
     живёт `redeliver`.
  3. Только если и этого мало — внешнее хранилище (в проекте уже есть R2 для медиа).
- **Проверка, без которой задача не закрыта:** после уборки досыл всё ещё находит файл для
  джобы с открытой доставкой (тест на пару «чистка + должок»), а не только «места стало
  больше».
- **Ключи:** `data/jobs` · `диск` · `retention` · `sqlite`
- **Связи:** досыл — `core/services/redelivery.py`
