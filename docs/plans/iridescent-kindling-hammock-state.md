## Задача: досыл несостоявшихся доставок

**Что просил j:** «сохранять chat_id + message_id при постановке; при failed помечать должок;
после починки досылать файл реплаем на исходное сообщение». Досылать **автоматически при
восстановлении**, не по команде.

**Почему отдельная таблица, а не колонки в `job`:** дедупликация по фингерпринту делает джобу
общей для всех, кто прислал ту же ссылку. Колонка `chat_id` в `job` хранила бы только
последнего — то есть фича молча теряла бы получателей, ровно тех, ради кого пишется.
Плюс `SQLModel.create_all` создаёт новые ТАБЛИЦЫ, но не добавляет колонки в существующие:
отдельная таблица заводится на проде сама, без миграции.

**Выборка «должок» = `Delivery.delivered_at IS NULL` И `job.status == failed`.** Из этого
следует, что помечать успешную доставку отдельным вызовом не нужно: удачный обычный путь
оставляет джобу `succeeded`, и она в выборку не попадает.

### Гочи, найденные по дороге

- 🛑 **Регистрацию доставки нельзя выставлять эндпоинтом.** Первая редакция сделала
  `POST /deliveries` с параметром `chat_id` — а `api` слушает `0.0.0.0:8033` без
  аутентификации, то есть кто угодно мог заставить бота слать файлы чужим людям. Поймал
  фоновый security-review после пуша, не автор и не тесты. Лечение — не токен, а удаление
  маршрута: бот живёт в том же процессе и ходил по HTTP сам к себе.
- 🛑 **Мутант-килл поймал два слепых теста** (первый прогон, 2 из 6 мутантов выжили): один
  тест падал из-за отсутствия токена в окружении, а не по проверяемой причине; второй не
  мог увидеть пропавший импорт модели, потому что импортировал её сам в шапке файла.
- `reply_to_message_id` в aiogram 3.31 ещё есть, но правильный путь —
  `reply_parameters=ReplyParameters(..., allow_sending_without_reply=True)`: иначе отправка
  падает целиком, если пользователь удалил своё сообщение.
- Досыл обязан быть ограничен по числу попыток, иначе при долгом простое площадки он
  превращается в вечный долбёж (и в лишний трафик к YouTube с флагованного адреса).

## Что осталось невозможным (не хвост, а вывод)

Разослать файлы тем **двенадцати**, кто писал боту до починки, нельзя: `chat_id` тогда нигде
не сохранялся, а Telegram не отдаёт боту историю обращений. Список получателей физически не
существует — досыл работает только вперёд, с тех, кто написал после PR #11.
